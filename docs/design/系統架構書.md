## 1. 架構總覽 (Architecture Overview)

本系統採用 **Zero-Trust Client-Side Encryption** 設計原則：後端永遠不接觸明文檔案或加密金鑰。所有加密/解密皆在客戶端完成，鏈上合約為唯一的權限判定來源（Single Source of Truth）。

### 1.2 三層架構

| 層級 | 職責 | 信任邊界 |
|------|------|----------|
| **Client 前端應用層** | UI、加密/解密、直接上傳 Walrus、錢包簽名 | 持有明文與加密金鑰 |
| **Off-chain 服務層** | API Gateway、Indexer、DB Cache、Workers | **永不接觸明文或金鑰** |
| **On-chain 合約層** | Pool 狀態機、權限判定、Metadata、Events | 唯一權限來源 (SSOT) |

## 3. On-chain 物件模型 (Sui Move)

### 3.1 物件關係總覽

```
Pool (shared object)
 ├── [dynamic_object_field] DataRoom
 │    ├── [dynamic_field] folder_keys: Table<FolderID, EncryptedKeySet>
 │    ├── [dynamic_field] memberships: Table<address, Membership>
 │    ├── [dynamic_object_field] Document (per doc_id)
 │    │    ├── [dynamic_field] versions: Table<u64, DocVersion>
 │    │    └── metadata (current version, status, encryption_scheme)
 │    └── folder_config (predefined structure)
 │
 └── state: PoolState (Draft → DD_In_Progress → IC_Review → ...)
```

### 3.2 核心物件定義

#### Pool

```move
struct Pool has key {
    id: UID,
    owner: address,
    borrower_info: BorrowerMeta,
    state: u8,  // PoolState enum
    created_at: u64,
    // DataRoom 透過 dynamic_object_field 附加，避免 Pool 物件過大
}
```

- `DataRoom` 以 `dynamic_object_field::add(pool, b"data_room", data_room)` 掛載
- 避免單一物件超過 Sui 的 ~256KB 限制

#### DataRoom

```move
struct DataRoom has key, store {
    id: UID,
    pool_id: ID,
    encryption_scheme: u8,  // 0 = AES, 1 = Seal
    seal_policy_id: Option<ID>,  // Seal engine 才有值
    folder_count: u64,
}
```

- `memberships: Table<address, Membership>` — 透過 dynamic field 掛載
- `folder_keys: Table<FolderID, EncryptedKeySet>` — 透過 dynamic field 掛載

#### Membership

```move
struct Membership has store, drop {
    role: u8,       // Owner=0, Editor=1, Reviewer=2, Viewer=3
    added_by: address,
    added_at: u64,
    folders_access: vector<FolderID>,  // 可存取的 folder 列表
}
```

- 儲存於 `Table<address, Membership>`，查詢 O(1)
- **不使用 `vector<Membership>`**：成員數可能增長至數百，vector 會撞 object size 限制

#### Document

```move
struct Document has key, store {
    id: UID,
    data_room_id: ID,
    folder_id: FolderID,
    current_version: u64,
    status: u8,     // NotReviewed=0, InReview=1, Reviewed=2, NeedsRevision=3
    doc_type: String,
    encryption_scheme: u8,  // 繼承自 DataRoom
    created_at: u64,
}
```

- 版本歷史 `Table<u64, DocVersion>` 透過 dynamic field 掛載
- **不使用 `vector<DocVersion>`**：文件版本數量不可預測

#### DocVersion

```move
struct DocVersion has store, drop {
    version: u64,
    walrus_blob_id: String,   // Walrus Blob ID（非 CID）
    content_hash: vector<u8>, // SHA-256 of plaintext (for integrity check)
    encrypted_size: u64,
    uploader: address,
    uploaded_at: u64,
}
```

### 3.3 Events（取代 stored AuditTrailEntry）

```move
// ===== Audit Events（不儲存為物件，僅 emit）=====

struct PoolStateChanged has copy, drop {
    pool_id: ID,
    from_state: u8,
    to_state: u8,
    changed_by: address,
    timestamp: u64,
}

struct DocumentUploaded has copy, drop {
    pool_id: ID,
    data_room_id: ID,
    doc_id: ID,
    version: u64,
    walrus_blob_id: String,
    uploader: address,
    timestamp: u64,
}

struct MembershipChanged has copy, drop {
    data_room_id: ID,
    member: address,
    action: u8,  // Added=0, Removed=1, RoleChanged=2
    role: u8,
    changed_by: address,
    timestamp: u64,
}

struct DocumentReviewStatusChanged has copy, drop {
    doc_id: ID,
    from_status: u8,
    to_status: u8,
    reviewer: address,
    timestamp: u64,
}

struct ICDecisionSubmitted has copy, drop {
    pool_id: ID,
    decision: u8,  // Approve=0, Reject=1, RequestChanges=2
    decision_doc_blob_id: String,
    submitted_by: address,
    timestamp: u64,
}
```

**設計決策：AuditTrailEntry 改為 Events**
- 原設計將 audit 存為 Sui 物件 → 每筆操作都產生新物件 → 成本爆炸
- 改為 Event emission：零儲存成本、Indexer 消費後寫入 PostgreSQL
- 鏈上可驗證（event 包含在 transaction effects 中）

## 4. 加密架構 (Dual-Engine Encryption)

### 4.1 Encryption Abstraction Layer

```
┌─────────────────────────────────────────────────────────────┐
│                     Client Encryption SDK                    │
│                                                              │
│   interface EncryptionEngine {                               │
│     encrypt(file: Uint8Array, ctx: EncryptCtx): EncBlob     │
│     decrypt(blob: EncBlob, ctx: DecryptCtx): Uint8Array     │
│   }                                                          │
│                                                              │
│   ┌─────────────────────┐    ┌────────────────────────────┐ │
│   │     AESEngine        │    │      SealEngine            │ │
│   │   (production, 預設)  │    │   (beta, 可選, 10% 折扣)   │ │
│   │                      │    │                            │ │
│   │ encrypt:             │    │ encrypt:                   │ │
│   │  AES-256-GCM +       │    │  Seal SDK encrypt under    │ │
│   │  per-folder key      │    │  policy object ID          │ │
│   │                      │    │                            │ │
│   │ decrypt:             │    │ decrypt:                   │ │
│   │  fetch encrypted key │    │  request key shares from   │ │
│   │  from Sui → local    │    │  Seal key servers →        │ │
│   │  decrypt key →       │    │  servers verify Move       │ │
│   │  local decrypt file  │    │  policy on-chain →         │ │
│   │                      │    │  reconstruct key locally   │ │
│   └─────────────────────┘    └────────────────────────────┘ │
│                                                              │
│   Document.encryption_scheme → SDK auto-routes to engine     │
└─────────────────────────────────────────────────────────────┘
```

### 4.2 AES Engine 流程（Production）

**加密（上傳）：**
```
1. Client 取得 folder 的 AES-256-GCM symmetric key
   （key 以 member 公鑰加密後存於 Sui dynamic field）
2. Client 在瀏覽器內以該 key 加密檔案
3. Client 直接上傳 encrypted blob → Walrus Publisher
4. Walrus 回傳 Blob ID
5. Client 或 Backend(sponsored) 將 metadata + Blob ID 寫入 Sui
```

**解密（下載）：**
```
1. Client 從 Sui 讀取 Document metadata（含 Blob ID）
2. Client 從 Sui dynamic field 取得用自己公鑰加密的 folder key
3. Client 在本地用私鑰解密 folder key
4. Client 從 Walrus Aggregator 下載 encrypted blob
5. Client 在本地用 folder key 解密檔案
```

**後端角色：零（不參與加密/解密路徑）**

### 4.3 Seal Engine 流程（Beta）

**加密（上傳）：**
```
1. Client 使用 Seal SDK，以 DataRoom 的 seal_policy_id 加密檔案
   （Seal SDK 內部產生 ephemeral key，以 policy object ID 作為加密條件）
2. Client 直接上傳 encrypted blob → Walrus Publisher
3. Walrus 回傳 Blob ID
4. Client 或 Backend(sponsored) 將 metadata + Blob ID 寫入 Sui
```

**解密（下載）：**
```
1. Client 從 Sui 讀取 Document metadata（含 Blob ID, seal_policy_id）
2. Client 向 Seal Key Servers 發送解密請求
3. Seal Key Servers 在鏈上執行 seal_approve() Move 函式
   → 驗證 caller 是否為 DataRoom member 且有權存取該 folder
4. 驗證通過 → Key Servers 各自回傳金鑰碎片 (key share)
5. Client 在本地重建解密金鑰（threshold reconstruction）
6. Client 從 Walrus Aggregator 下載 encrypted blob
7. Client 在本地解密檔案
```

**後端角色：零（不在解密路徑中）**
**Seal Key Servers：不持有完整金鑰，只持有碎片，且每次解密都驗證鏈上 policy**

### 4.4 引擎差異比較

| 面向 | AES Engine | Seal Engine |
|------|-----------|-------------|
| 金鑰管理 | Per-folder symmetric key, 以 member 公鑰包裝 | Seal threshold encryption, policy-based |
| 權限判定 | Move 合約控制 key 存取 | Seal Key Servers 執行 Move policy |
| 成員移除 | Rotate folder key + re-encrypt | 更新 Move policy，Seal servers 即時拒絕 |
| 離線存取 | 有 key 即可（需妥善管控） | 必須連線 Seal Key Servers |
| 定價 | 100% 正價 | 90%（Beta 10% 折扣） |
| SLA | Production SLA | Best-effort Beta |
| 合規覆蓋 | SOC 2 / ISO 27001 | 不納入正式審計 |

### 4.5 Per-Folder Key 架構（ADR-01）

```
DataRoom
 ├── Folder: Legal
 │    └── folder_key_legal (AES-256-GCM)
 │         ├── encrypted_for(alice_pubkey) → stored in Sui dynamic field
 │         ├── encrypted_for(bob_pubkey)   → stored in Sui dynamic field
 │         └── encrypted_for(carol_pubkey) → stored in Sui dynamic field
 │
 ├── Folder: KYC (highly sensitive)
 │    └── folder_key_kyc
 │         ├── encrypted_for(alice_pubkey)  // only Owner & Compliance
 │         └── encrypted_for(dave_pubkey)
 │
 └── Folder: Reports
      └── folder_key_reports
           ├── encrypted_for(alice_pubkey)
           ├── encrypted_for(bob_pubkey)
           ├── encrypted_for(carol_pubkey)
           └── encrypted_for(eve_pubkey)   // Viewer can read Reports

成員移除流程（例如移除 Bob）：
1. Rotate Bob 有權存取的 folder keys (Legal, Reports)
2. 用新 key re-encrypt 受影響 folder 的所有文件
3. 將新 key 以剩餘 members 的公鑰加密後更新 Sui dynamic field
4. Bob 持有的舊 key 無法解密新版文件
```

### 5.2 Session 設計

| 參數 | 值 | 說明 |
|------|---|------|
| Session store | Redis | 支援水平擴展、原子操作 |
| JWT expiry | 可設定（建議 4h） | 過期後需重新簽名 |
| Refresh mechanism | Sliding window | 活躍使用時自動延長 |
| Session payload | `{ address, role_cache, pool_ids }` | 減少鏈上查詢 |
| Invalidation | 登出 / 權限變更時立即失效 | Redis DEL |

### 5.3 交易簽名分級（ADR-02）

| 操作類型 | 簽名方式 | 說明 |
|---------|---------|------|
| Pool 狀態轉移 | **用戶親簽** | 不可否認性 |
| 成員新增/移除 | **用戶親簽** | 高權限操作 |
| IC 決議提交 | **用戶親簽** | 法律效力 |
| 文件 metadata 寫入 | Backend sponsored TX | 提升 UX |
| Audit event emit | Backend sponsored TX | 低敏感度 |
| Document review 狀態 | **用戶親簽** | 審核責任歸屬 |

**Backend 永不持有用戶私鑰**。Sponsored transactions 中 backend 只付 gas，交易邏輯仍由用戶或 backend 自身 address 執行。

## 6. Off-chain 服務架構

### 6.1 API Gateway (NestJS)

```
API Gateway 職責：
  ✅ 認證與 Session 管理
  ✅ 交易構建（TransactionBlock builder）
  ✅ Gas sponsoring（Sui sponsored transactions）
  ✅ Metadata CRUD（寫入/查詢 PostgreSQL cache）
  ✅ WebSocket 推送（即時 UI 更新）
  ✅ Rate limiting / throttling

  ❌ 加密 / 解密檔案
  ❌ 接觸明文
  ❌ 持有用戶私鑰或加密金鑰
  ❌ 充當 Walrus 上傳 proxy
```

### 6.2 Event Indexer

**重要：Sui JSON-RPC 將於 2026-04 deprecated。系統使用 gRPC streaming 或 GraphQL 替代。**

```
┌──────────────┐     gRPC streaming      ┌──────────────┐
│  Sui Network │ ───────────────────────> │  Indexer      │
│  (Events)    │                          │  Service      │
└──────────────┘                          │               │
                                          │  - Filter by  │
                                          │    package ID │
                                          │  - Parse event│
                                          │    payload    │
                                          │  - Write to   │
                                          │    PostgreSQL  │
                                          │  - Persist    │
                                          │    cursor/    │
                                          │    checkpoint │
                                          └───────┬──────┘
                                                  │
                                                  ▼
                                          ┌──────────────┐
                                          │  PostgreSQL   │
                                          │  (Off-chain   │
                                          │   cache)      │
                                          └──────────────┘
```

#### Indexer 設計要點

| 面向 | 設計 |
|------|------|
| 資料來源 | gRPC streaming（primary）/ GraphQL（fallback） |
| Cursor 持久化 | 每批 events 處理完後將 checkpoint 寫入 DB |
| 冪等處理 | 以 `(tx_digest, event_seq)` 作為唯一鍵，重複事件自動跳過 |
| 全量重建 | 支援從 genesis 或任意 checkpoint 重新 index，DB 可完全從鏈上重建 |
| 監聽事件 | `PoolStateChanged`, `DocumentUploaded`, `MembershipChanged`, `DocumentReviewStatusChanged`, `ICDecisionSubmitted` |

#### Off-chain DB 定位

```
╔══════════════════════════════════════════════════════════════════╗
║  Off-chain DB (PostgreSQL) 是 CACHE，不是 source of truth       ║
║                                                                  ║
║  ● 用途：全文檢索、列表分頁、Dashboard 聚合查詢                  ║
║  ● 權限判定：永遠查鏈上合約，不信任 DB cache                     ║
║  ● 資料不一致時：以鏈上為準，觸發 re-index                       ║
║  ● DB 丟失/損毀：從鏈上 events 完全重建，零資料損失              ║
╚══════════════════════════════════════════════════════════════════╝
```

### 6.3 Background Workers

#### Walrus Blob Renewal Worker

```
職責：自動在 Walrus 儲存 epoch 到期前 renew blobs

流程：
1. 定期掃描 DB 中所有 active Pool 的 Blob IDs
2. 檢查每個 blob 的 epoch 過期時間
3. 在過期前 N epochs 發送 renew 交易
4. 更新 DB 中的 epoch 資訊
5. 失敗時 → retry + alert

費用：平台統一代付，計入 SaaS 訂閱費（ADR-03）
```

#### Notification Service

```
觸發來源：Event Indexer 推送 parsed events

通知類型：
  - Pool 狀態變更 → 通知相關成員
  - 新文件上傳 → 通知 Reviewers
  - Document review 完成 → 通知 Owner
  - 成員新增/移除 → 通知被操作者
  - 訂閱到期提醒 → 30 天前開始（ADR-03）

通知管道：
  - 平台內 WebSocket 即時推送
  - Email（SMTP）
  - 未來：Telegram / Slack webhook
```

#### Backup Worker（Seal Beta 專用）

```
職責：為使用 Seal Engine 的 Pool 維護 off-chain AES 加密備份

流程：
1. 監聽 DocumentUploaded events（encryption_scheme = Seal）
2. 從 Walrus 下載 encrypted blob
3. 使用平台 backup key（AES-256-GCM）再次加密
4. 上傳至 S3（或相容的 object storage）
5. 記錄 mapping: blob_id → s3_key

目的：若 Seal 出現不可恢復問題，可用 AES 備份恢復
揭露：備份策略對客戶透明揭露（ADR-07）
```

## 7. 儲存架構 (Walrus Integration)

### 7.1 Walrus 核心概念

| 概念 | 說明 |
|------|------|
| **Blob ID** | Walrus 的內容識別碼（**非 IPFS CID**） |
| **Publisher** | 接收上傳請求的 Walrus 節點 |
| **Aggregator** | 提供下載服務的 Walrus 節點 |
| **Epoch** | Walrus 儲存計費週期，blob 需在到期前 renew |

### 7.2 上傳流程

```
Client (Browser)
     │
     │  1. 加密檔案（AES or Seal engine, client-side）
     │
     │  2. PUT /v1/blobs  →  Walrus Publisher
     │     Body: encrypted_blob
     │     ──────────────────────────>
     │                                Walrus Publisher
     │     <──────────────────────────
     │     Response: { blob_id, epoch_info }
     │
     │  3. 將 metadata 送至 API Gateway
     │     { blob_id, content_hash, size, folder_id, ... }
     │     ──────────────────────────>
     │                                API Gateway
     │     4. 構建 Sui TX: add_document_version(
     │           data_room, doc_id, blob_id, ...)
     │        可能為 sponsored TX
     │     ──────────────────────────>
     │                                Sui Network
     │     5. Emit DocumentUploaded event
     │     ──────────────────────────>
     │                                Indexer → PostgreSQL
```

### 7.3 下載流程

```
Client (Browser)
     │
     │  1. 查詢 Document metadata（from DB cache or Sui）
     │     → 取得 blob_id, encryption_scheme
     │
     │  2. GET /v1/blobs/{blob_id}  →  Walrus Aggregator
     │     ──────────────────────────>
     │     Response: encrypted_blob
     │     <──────────────────────────
     │
     │  3a. (AES Engine)
     │      讀取 Sui dynamic field → 取得 encrypted folder key
     │      → 用自己私鑰解密 key → 用 key 解密 blob
     │
     │  3b. (Seal Engine)
     │      向 Seal Key Servers 請求 key shares
     │      → Seal servers 驗證 Move policy on-chain
     │      → 取得 shares → 本地重建 key → 解密 blob
     │
     │  4. 顯示明文檔案（PDF.js / browser native render）
```

### 7.4 File Preview Pipeline

```
解密後的檔案（Client-side memory）
     │
     ├── PDF  → PDF.js 渲染（in-browser, 不離開客戶端）
     ├── 圖片 → <img> tag with blob URL
     ├── 文字 → Syntax-highlighted viewer
     └── 其他 → 下載 prompt

注意：明文僅存在於 browser memory，不寫入 disk
關閉 tab / 離開頁面 → 自動 GC
```

### 7.5 Blob 生命週期管理

```
Blob 建立
  │
  ├── Walrus Renewal Worker 定期檢查
  │    └── epoch 到期前 → 自動 renew（平台代付）
  │
  ├── Pool 正常運作中 → 持續 renew
  │
  ├── 訂閱到期 → ADR-03 流程：
  │    ├── 到期前 30 天：提醒
  │    ├── 到期日：平台墊付（14 天寬限）
  │    └── 寬限期後：停止 renew → blob 可能被 Walrus 清除
  │
  └── Pool 結案/歸檔 →
       └── 依合約保留年限繼續 renew
       └── 超過保留期 → 停止 renew
```

### 9.2 關鍵監控指標

| 類別 | 指標 | Alert 閾值 |
|------|------|-----------|
| **API Gateway** | Request latency (p50/p95/p99) | p99 > 2s |
| | Error rate (5xx) | > 1% |
| | Active sessions | — (dashboard) |
| **Seal Engine** | Key server 可用率 | < 99.5% |
| | Encrypt/decrypt latency | p99 > 3s |
| | Decrypt failure rate | > 0.5% |
| **Walrus** | Upload success rate | < 99% |
| | Blob renewal success | 任何失敗立即 alert |
| | Blob 即將到期（未 renew） | 距到期 < 2 epochs |
| **Indexer** | Event processing lag | > 30s behind chain tip |
| | Checkpoint persistence | 連續 3 次失敗 |
| **Sui TX** | Sponsored TX failure rate | > 5% |
| | Gas budget 餘額 | < 10 SUI |

### 9.3 Logging & Audit

```
Log 層級：
  - API Gateway: structured JSON logs (request_id, address, action)
  - Indexer: event processing logs with checkpoint info
  - Workers: task execution logs with timing

注意：logs 中永不記錄：
  - 加密金鑰或 key material
  - 檔案內容或明文
  - 完整 JWT tokens（僅記錄 hash）
```

### 9.4 Incident Response

| 事件 | 影響 | 處置 |
|------|------|------|
| Seal Key Server 不可用 | Seal Engine 池無法解密 | 顯示友善錯誤、alert on-call、**不 fallback 至 AES** |
| Walrus Publisher 不可用 | 無法上傳 | retry + 切換 Publisher endpoint |
| Walrus Aggregator 不可用 | 無法下載 | retry + 切換 Aggregator endpoint |
| Indexer lag > 5 min | UI 顯示過期資料 | alert + 檢查 gRPC 連線 |
| PostgreSQL down | API 查詢失敗 | Fallback 直接查 Sui（降級模式） |
| Gas 餘額不足 | Sponsored TX 失敗 | Auto-alert + 手動充值 |
